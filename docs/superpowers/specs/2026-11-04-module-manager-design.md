# 插件与模块管理器设计

状态：用户已于 2026-11-04 确认，开始实现。

分支：`feat/module-manager`，基于 `68ed6ab`。

## 目标

在设置中增加“插件与模块”页面，统一管理可选模型资源。先接入体积光使用的 DepthMini，后续深度模型及依赖这些模型的功能均通过同一目录、生命周期和能力接口接入。

本次必须覆盖模型来源、实际下载进度、统一存放位置、安装、启用/禁用、卸载、错误恢复、中英文界面及已有模型缓存迁移。

## 方案选择

| 方案 | 实现范围与取舍 |
| --- | --- |
| A：统一模块管理器，首个模块为 DepthMini（推荐） | 内置模块目录描述资源与能力，管理器负责下载、安装及状态，模型适配器负责推理。后续增加模型可复用设置页面和管理流程。 |
| B：仅增加深度模型设置页 | 初期改动较少，但后续其他模块需要重新抽取公共管理逻辑。 |
| C：完整第三方可执行插件系统 | 需要定义扩展 API、二进制兼容和插件分发协议，范围远大于目前的可选模型需求。 |

采用 A。第一版管理应用内登记的可选资源模块，通过代码登记新模块和推理适配器。自定义下载地址、任意模型导入、插件市场、动态执行第三方代码及自动模型更新不包含在第一版中。

## 设置页面

沿用现有侧栏与详情布局，增加“插件与模块 / Plug-ins & Modules”分类。

页面顶部展示统一存放目录及“在访达中显示”，展示已安装模块的磁盘占用汇总。第一版使用系统 Application Support 目录，不提供目录搬迁操作；路径由系统 API 获取，不硬编码用户名。

每个模块展示：

- 名称、用途、当前版本和状态。DepthMini 的用途说明为“体积光与深度图提取”。
- 下载大小与实际安装占用，分别标注，避免将编译后体积当成下载体积。
- 发布者、模型来源主页、固定版本发布页、下载来源及许可证/来源说明；提供可点击链接。
- DepthMini 标明蒸馏来源为 Depth Anything V2 Small，以及 README 记录的 torchvision MobileNetV3 权重来源。保留各自许可证归属，不将整个应用的 MIT 许可证作为模型许可证。
- 未安装时提供“下载”；下载中显示百分比与“已下载 / 总大小”，并可取消；失败时显示原因并提供“重试”。
- 校验、编译和迁移阶段显示明确阶段名称及不定进度，下载达到 100% 不等于模型已可用。
- 已安装时提供启用开关和卸载操作；卸载确认中说明依赖功能将使用估算效果，并注明后续需手动下载才能恢复模型。
- 模型不可用时，体积光面板给出简短状态说明和“管理模块”入口，直接打开对应设置分类。

页面与错误文案同时提供简体中文和英文，沿用现有 `L10n`、`applicationLanguage()` 和无障碍标识。

## 来源与模块目录

每个 `ModuleDescriptor` 至少登记：稳定 ID、显示名称、版本、简介、能力类型、发布者、来源/发布/许可链接、各资源的下载 URL、包内相对路径、预期大小与 SHA-256、安装方式及旧缓存位置。

DepthMini 登记为 `depth-mini`，固定版本为 `depth-model-1`。正式下载继续使用现有上游发布资产，禁止通过 `latest` 在后台隐式替换推理模型。固定摘要仍作为校验依据，不能用下载文件自己提供的摘要替代。

来源和大小随内置目录发布；打开设置只读取本地状态，不请求 GitHub API。以后登记其他模型时需要完整填写元信息，并为不同输入输出定义对应适配器，不能假设所有 Core ML 模型均使用 DepthMini 的 `image` / `depth` 接口。

## 统一存放与安装事务

根目录由 `FileManager` 的 Application Support URL 加上 `Compositor/Modules/` 得到。当前应用启用了沙盒，通常实际位于 `~/Library/Containers/com.wonderassembly.compositor/Data/Library/Application Support/Compositor/Modules/`；无沙盒构建才使用 `~/Library/Application Support/Compositor/Modules/`。设置中显示实际解析后的路径，不展示与运行环境不符的简化路径。

```text
Modules/
  depth-mini/
    depth-model-1/
      DepthMini.mlpackage/
      DepthMini.mlmodelc/
      installation.json
  .staging/
    <operation-uuid>/
```

- 新安装保留经过校验的源包和编译结果；安装记录包含模块 ID、版本、目录指纹、来源和安装时间，便于状态恢复与诊断。
- 下载、校验、编译和加载验证在临时目录内完成，成功后才提升为正式安装；临时目录与正式目录处于同一根目录，便于原子发布。
- 同一模块只有一个安装任务；设置下载与功能触发的请求共享任务和进度，不重复下载。
- 取消、失败及崩溃残留不能形成“已安装”状态。启动时仅清理本管理器自己的过期暂存目录；不会清理其他应用缓存。
- 下载写入文件，避免将未来的大模型整体保存在内存中；检查 HTTP 状态、大小和摘要，并限制实际接收大小。包内路径必须留在安装目录内。
- 编译成功还需验证模型可加载及预期输入输出。只有通过这些步骤才能标记可用。
- 磁盘不足、写入失败、校验失败、编译失败、下载失败分别形成可本地化的错误；失败不删除原先可用的正式版本。

### 旧缓存迁移

首次扫描发现现有 DepthMini 编译缓存时，先复制至暂存区，验证 Core ML 可加载及输入输出匹配，成功后迁入统一目录并写入安装记录，最后清理确认已迁移的旧副本。

旧缓存只有编译结果，不能重新计算并匹配原始下载文件的 SHA-256。安装记录明确标记其为“旧版编译缓存迁入”，不能声称已重新验证源包摘要。迁移失败保留旧缓存并在设置中报告原因，可通过下载恢复。

## 下载进度与取消

使用下载任务的实际字节回调，聚合所有资源的已下载字节数。DepthMini 的分母使用上述固定资产大小；后续无法取得总长度的任务使用不定进度，不伪造百分比。

状态包括：未安装、下载中、校验中、编译中、迁移中、已安装、卸载中和失败。启用偏好独立于安装状态；“已安装”和“模型已加载到内存”也分别表达。

取消会取消该模块的共享下载任务、清理其暂存内容并通知所有等待者。重试建立新的操作 ID；旧任务迟到的进度和完成回调不能覆盖新任务状态。第一版不承诺断点续传，重试可重新下载。

## 自动下载、启用与卸载

- 对从未管理过的 DepthMini，保留现有首次使用自动下载行为；设置页也可以主动下载。
- 用户关闭启用开关后，停止为该模型接受新的准备/推理请求；体积光继续使用已有的估算路径。启用偏好跨启动保存。
- 用户取消自动下载或卸载时，关闭该模块的自动获取许可，避免再次打开体积光立即重新下载。可在设置中主动“下载”恢复许可与安装。
- 已安装但被禁用的模块可直接重新启用；重新启用不重复下载已有有效文件。
- 正在推理时，禁用先阻止新的请求并使缓存失效；已开始的推理可以结束，但其过期结果不能重新写入缓存或应用到当前预览。
- 卸载等待仍持有模型资源的推理完成后再删除该模块的文件。等待期间显示“卸载中”；不会误删其他模型或用户项目。

## 架构与接入规则

建议新增 `Compositor/Modules/`，存放模块描述、内置目录、下载/安装存储和模型运行适配器。设置视图放在 `Compositor/UI/Settings/Modules/`，推理结果类型和 DepthMini 适配代码放在 `Compositor/Modules/Depth/`。

职责分为三个部分：

1. **模块存储与安装层**：串行协调各模块操作，管理正式/暂存文件、下载任务、校验、编译和安装记录。磁盘、网络和 Core ML 编译不阻塞主线程。
2. **可观察管理器**：在主线程发布模块列表、阶段、字节进度和用户偏好；设置和功能入口共用它，不各自维护状态。
3. **深度模型适配层**：提供准备、可用性和深度推理接口，将模型输出统一为现有 `DepthMap` 约定（近处为 1，远处为 0，按行排列）。体积光只依赖该能力，不再拥有下载地址和目录结构。

新增模型必须登记目录项和能力适配器。新增依赖深度估计的功能必须通过统一准备/推理入口使用模型，不得直接下载、编译或自行建立模型缓存目录。登记第二种深度模型时，再增加默认模型选择界面。

运行状态具有递增代号，模型安装、启用、禁用、卸载或版本变更时更新。`DepthModel` 推理缓存和 `VolumetricLighting.Prepared` 的深度缓存都带上该代号；旧代号的结果不可复用或重新发布。打开的体积光预览在可用性变更时重新计算，避免界面关闭开关后仍使用旧深度图。

保留当前五秒预览等待与离线回退语义；禁用或已取消自动获取时立即使用估算路径，不再显示持续下载。深度图提取在模型不可用时提供明确状态和管理入口。

不修改 `.comp` 格式、已保存的滤镜参数、快捷键标识或现有模型输出方向。

## 验证与验收

新增自动化测试使用临时目录、独立偏好存储及可控制的网络/编译适配器，不访问真实用户模型目录，也不依赖公网。

- 目录项和来源固定性；包路径约束；三个现有文件的摘要与大小。
- 字节进度聚合、未知总长度、HTTP 失败、大小/摘要不匹配、取消及重试。
- 多个调用共享同一安装任务；迟到回调不得覆盖取消或重试后的状态。
- 成功后原子安装；失败保留可用版本；暂存清理、磁盘错误与编译错误。
- 启用/禁用持久化、卸载后不自动重新下载、恢复下载、旧缓存迁移与迁移失败保留。
- 正在推理时的禁用/卸载；推理缓存和体积光预览缓存的状态代号检查。
- 原体积光首帧等待、五秒估算预览、离线回退、深度提取和重复滤镜行为。
- 中英文目录键、格式参数、设置分类及错误展示。

先运行模块、语言和体积光专项测试，再运行完整 `CompositorTests`。检查 CI 路径规则覆盖新模块目录及相关回归测试。最后在开发构建中验证设置分类、来源链接、下载阶段、取消/重试、启用/禁用和卸载；如能下载真实 DepthMini，单独记录模型编译与推理证据，不能用模拟测试替代。

同步更新中英文 README、源码结构及模块接入文档。实现与测试完成后进行独立审查，创建本地提交，不推送、不替换系统安装。
